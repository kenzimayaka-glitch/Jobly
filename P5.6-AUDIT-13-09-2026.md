# JOBLY — P5.6 AUDIT TECHNIQUE — 13/09/2026

## Résultat

### 1. Quota atomique
**CORRIGÉ.**

Ancien risque :
`SELECT SUM(AiUsage)` → contrôle → `INSERT AiUsage`.

Ce pattern permettait à deux requêtes concurrentes de voir le même quota disponible.

Nouveau mécanisme :
- PostgreSQL `reserve_ai_credit(...)`
- verrou `pg_advisory_xact_lock` par utilisateur
- calcul + insertion dans la transaction
- idempotence `userId + requestHash`
- index unique correspondant.

### 2. Minimisation PII
**CORRIGÉE AU NIVEAU DU GATEWAY.**

- whitelist des champs d'entrée par opération
- limite de 4000 caractères sur les textes
- masquage email/téléphone
- nettoyage des champs profil et expérience utilisés dans le contexte.

### 3. Provider
**NON ACTIVÉ.**

Le fallback déterministe reste le comportement actuel. Aucun appel provider externe de production n'est introduit par ce checkpoint.

### 4. Validation DB Supabase — tests exécutés

Les contrôles suivants ont été confirmés sur la base Supabase de test :

| Contrôle | Résultat | Verdict |
|---|---|---|
| Auth → User | 1 ↔ 1 | ✅ |
| Correspondance UUID | identique | ✅ |
| User → Subscription | FREE / ACTIVE | ✅ |
| AiUsage | 1 réservation / 1 crédit | ✅ |
| Idempotence `requestHash` | 1 seule occurrence | ✅ |
| Protection DB | `UNIQUE ("userId", "requestHash")` | ✅ |
| TEST 7 — quota maximum FREE | `allowed=true`, `used_credits=5`, `remaining_credits=0` | ✅ |

**Conclusion des tests 7 et 8 :** le quota FREE est plafonné à 5 crédits et toute réservation supplémentaire est refusée sans créer de nouvelle ligne `AiUsage`.
