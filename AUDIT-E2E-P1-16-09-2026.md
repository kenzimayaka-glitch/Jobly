# JOBLY — AUDIT E2E P1 — 16/09/2026

## Objectif
Fermer les parcours critiques et supprimer les portes mortes/incohérences détectables statiquement sur la version V7.3.

## Périmètre
- 55 routes `page.tsx`.
- 42 routes API.
- Navigation interne `href`, `router.push`, `router.replace`.
- Parcours Recruiter, Talent, Mobility Partner.
- Cohérence des données affichées : suppression des chiffres/identités fictifs.
- Compilation TypeScript disponible dans l'environnement, mais dépendances npm absentes.

## Résultats
### Navigation
- 55 routes détectées.
- 42 routes API détectées.
- 0 `href="#"`.
- 0 destination interne littérale non résolue par correspondance de route.
- Les routes dynamiques `[id]` sont correctement reconnues dans le scan.

### P1 — corrections réalisées
1. **Recruiter — création d'offre**
   - `/recruiter/jobs/new` était une page de façade qui annonçait le formulaire comme non branché.
   - Correction : extraction du formulaire réel dans `components/recruiter/RecruiterJobForm.tsx`.
   - `/recruiter/jobs/new` utilise maintenant ce formulaire.
   - `/recruiter/jobs/[id]` utilise le même composant en mode édition.
   - Création, brouillon et publication utilisent `/api/recruiter/jobs` déjà présent.
   - Import d'une offre par URL conservé.

2. **Recruiter — métriques fictives**
   - `+3 cette semaine` et `+12 depuis hier` étaient statiques.
   - Correction : calcul à partir des `createdAt` réels des offres/candidatures chargées.

3. **Recruiter — validation fictive**
   - Une validation affichait « Profil entreprise vérifié – Orange Cameroun » sans lien avec le profil courant.
   - Correction : affichage générique et honnête de contrôles UI réellement effectués.

4. **Mobility Partner — claim GPS non démontré**
   - « GPS Actif » était affiché sans preuve de capteur/runtime dans cette page.
   - Correction : « Rapports à jour », cohérent avec l'API réellement appelée.

5. **Mobility Partner — contexte d'authentification**
   - Le layout appelait `/api/mobility/partner/me` sans transmettre le bearer token.
   - Correction : récupération de la session Supabase et envoi du token Authorization.

6. **Types TypeScript — erreurs indépendantes des dépendances**
   - `aiGateway.ts` : `JIA_NAME` utilisé comme type → corrigé en `typeof JIA_NAME`.
   - `opportunityAggregator.ts` : suppression de l'option `next` de `RequestInit` pour compatibilité standard et typage explicite des entreprises.

## Validation compilation
`tsc --noEmit` a été lancé.

Le résultat est actuellement pollué par l'absence de `node_modules` dans l'environnement : React, Next, Supabase, Node types, etc. ne peuvent pas être résolus.

Après filtrage de ces erreurs de dépendances, des erreurs de typage préexistantes restent dans plusieurs écrans/API (notamment applications, auth callbacks, mobilité, Career Brain et la page d'accueil). Elles doivent être traitées après installation des dépendances afin de distinguer les vrais diagnostics des cascades provoquées par les modules absents.

## Limites importantes
Cet audit est un audit de code et de continuité statique. Il ne peut pas certifier :
- un clic réel dans un navigateur ;
- une session Supabase réelle ;
- les RLS Supabase ;
- les secrets Vercel ;
- le provider de paiement réel ;
- les webhooks externes ;
- les APIs ONG tierces ;
- les comportements mobile réels ;
- le build final tant que les dépendances npm ne sont pas installées.
